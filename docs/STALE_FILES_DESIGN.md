# Removing files a game update drops (design, not implemented)

Evidence: Far Far West (steam-3124540) kept 9 paks from an older build (pakchunk0_s3optional/s4/s5 .pak/.ucas/.utoc); Unreal mounted them and crashed with "Missing shader resource" until they were moved away (2026-11-24). Design drafted by Codex (gpt-6.2-sol), reviewed.

**Get the shipped file list from depotkit’s plan.** The C API exposes manifest totals and platform hints, but no filenames. Add an ABI-compatible `depotkit_download_with_inventory` in [include/depotkit.h](../depotkit/include/depotkit.h:95) and [src/api.cpp](../depotkit/src/api.cpp:132), keeping `depotkit_download` as-is for existing callers. Thread an optional visitor through [src/engine/engine.hpp](../depotkit/src/engine/engine.hpp:24) into [runDownload](../depotkit/src/engine/engine.cpp:288). Emit depot and manifest IDs, entry type, decrypted relative path and content SHA-1 before the verification and empty-entry shortcuts. Report which depots completed planning, including empty manifests. The plugin copies callback data and uses it only after `DEPOTKIT_OK`. This reuses the exact selected, decrypted manifests without reparsing them. If shipped locally first, apply these changes to the configure-time copy in [harden_depotkit.py’s `main`](cmake/harden_depotkit.py:313).

**Track ownership in steamidra.** Collect inventory in [runDepotkit](src/install_pipeline.cpp:478). In [runInstallPipeline](src/install_pipeline.cpp:766), reconcile after download and the final cancellation check, before `embedOnlineFix` and launch resolution. Serialize operations per install root. Write `.arachnel-steamidra-files` atomically with `QSaveFile`. Use versioned UTF-8 JSON with app ID, selected OS, depot and manifest IDs as decimal strings, and per-depot entries containing slash-separated relative path, type and SHA-1 hex for regular files. Record it on successful install, update and verify. If a requested depot was skipped, preserve the prior marker and skip cleanup. If a previously tracked depot drops out of the request, carry its ownership forward and protect its paths until there is authoritative evidence of removal. Missing relay data and DLC selection changes can both look like removal.

**Delete only proven obsolete files.**

- Compare prior entries against the union of current paths and retained depot paths, including directory entries. Delete only a prior regular file whose path is absent and whose current bytes still match its prior manifest hash. Missing files count as resolved. Preserve modified files, entries without usable hashes, and reserved fix and marker names case-insensitively anywhere in the tree, including the listed Sprout files and Steam API backups.
- Validate both inventories. Reject absolute, traversal, drive, UNC and alternate-stream paths, and refuse to traverse symlinks or Windows reparse points. Use the host filesystem’s path semantics. On case-sensitive ext4, `Old.pak` and `old.pak` can be distinct and the obsolete spelling can be removed. On case-insensitive Windows directories, protect aliases of current paths. Skip ambiguous identities.
- Leave empty directories in the first implementation. Persist the new inventory together with pending deletion candidates before unlinking, then atomically drop resolved candidates. Log and retain failed removals for a later retry, including Windows sharing violations. A failed or cancelled download leaves both cleanup and marker untouched.

**First verify records a baseline.** A `.pak`, `.ucas` or `.utoc` under a shipped directory could be a mod. The nine existing Far Far West files need manual quarantine or a trusted inventory of the build actually installed, with their bytes checked against that inventory.

**Existing warning and remaining risks.** The message comes from Arachnel’s [`CoreController::warnAboutStaleContentAfterUpdate`](../Arachnel/src/core/catalog/catalog_facade_install.cpp:416). It logs and shows a notice when at least two candidate folders’ newest files are over a day older than the newest scanned file. It has no ownership data and will miss stale individual files beside fresh ones. Remaining risks include overlapping depots with conflicting hashes, external filesystem races during cleanup, and file-to-directory transitions that can block the download before post-success cleanup runs. Preserve disputed files and surface blocked cleanup.
